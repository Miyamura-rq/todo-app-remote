## 2-1 HTML の基本

| 用語 | 例：`<a href="https://example.com">例</a>` |
|---|---|
| タグ | `<a href="...">` と `</a>` |
| 要素 | 全体（画面の部品1つ分） |
| 属性 | `href="..."`（開始タグの中に書く追加の情報） |
| 空要素 | `<meta>` `<br>` `<input>` のように終了タグがないもの |

- 全体の形：`<!DOCTYPE html>` → `<html lang="ja">` → `<head>`（画面に出ない情報）＋ `<body>`（画面に出る中身）
- `<meta charset="UTF-8">` は `<head>` の**最初**に書く。ブラウザは上から読むので、日本語より前に文字コードを伝える
  - 消しても表示が変わらなかったのは、ブラウザが推測したから（既定が UTF-8 なのではない）
  - 文字コードを伝える方法は2つ：サーバーのヘッダー（`Content-Type: text/html; charset=utf-8`）と `<meta charset>`
- **HTML は間違いがあってもエラーを出さない**（`<hooter>` も表示された）。おかしいときは Elements タブで「ブラウザが実際に作った形」を見る
- **中に入れてよい要素は決まっている**：`<p>` の中に `<ul>` を書くと、ブラウザが `<p>` を閉じてしまう。考え方は「文章の中に入れて自然か」。迷ったら MDN の「許可されている内容」を見る（早見表の 10 章）
- VS Code で `!` → `Tab` でひな形が入る。`lang="en"` は `ja` に直す（`jp` は国の記号）

## 2-2 ToDo 画面の骨組み

### 使った要素
| 区画 | 要素 | 選んだ理由 |
|---|---|---|
| 上部 | `<header>` ＋ `<h1>` | アプリ名はページの題名。主な内容（`<main>`）ではない |
| 入力 | `<form>` ＋ `<label>` ＋ `<input>` ＋ `<button type="submit">` | 下の「`<form>` で囲む理由」 |
| 一覧 | `<ul>` ＋ `<li>` | ToDo の並びに順番の意味はない（あるなら `<ol>`） |
| 1件 | `<input type="checkbox">` ＋ `<label>` ＋ `<time>` ＋ `<button type="button">` | ToDo の文字をラベルにすると、文字のクリックでチェックが切り替わる |
| 件数 | 一覧のあとの `<footer>` ＋ `<p>` ＋ `<span>` | 件数は「一覧という区画」の情報。数字は JS で書き換えるので `<span>` で囲む |

### `<form>` で囲む理由
- 入力欄で **Enter を押すと送信**できる
- **`required` などのチェック**が働く
- 中の入力欄の値（`name` つき）をまとめて送れる

送信先（`action`）と送り方（`method`）を書かないと、**同じ URL に GET で送る**。値は URL のクエリ（`?todo=...`）につく。`name` がない入力欄の値は送られない。

### `id` と `for`
| 属性 | つける場所 | 意味 |
|---|---|---|
| `id` | 指される側（**入力欄**） | 名札。ページの中で1つだけ |
| `for` | 指す側（**ラベル**） | 「この名札の入力欄のためのラベル」 |

`id` が重なると、`for` はページの中で最初に見つかったものを指してしまう（フォームのラベルが効かなくなった）。

### 入力欄の属性
`placeholder`（入力例）、`required`（必須）、`maxlength`（最大文字数）、`name`（送るときの名前）、`checked`（チェック済み）。ほかの属性と `type` の全22種類は早見表の 7 章。

**ブラウザのチェックは親切な機能**。開発者ツールで外せるうえ、ブラウザを使わずにリクエストを送ることもできるので、**本当の守りはサーバー側**（ステップ8）。

## 2-3 CSS の基本

```css
セレクタ {
    プロパティ: 値;
}
```

- `<head>` に `<link rel="stylesheet" href="style.css">` で読み込む
- **class 名は見た目ではなく状態・役割でつける**（`done`、`delete-button`）。デザインを変えても HTML を直さずに済む。ステップ3で JS から探すときにも使う
- **継承**：`color` や `font-family` は親から引き継ぐ。ただし `<input>` `<button>` `<a>` は引き継がない（`font: inherit` で引き継がせる）
- **直接書いたほうが勝つ**、同じ強さなら**あとに書いたほうが勝つ**（詳細度）
- **CSS も間違いでエラーを出さず、その行を無視する**（`font-coler`、`#` の抜けた `8FA59F`）。Styles 欄の取り消し線と ⚠、VS Code の波線で見つける
- 開発者ツールの **Styles 欄**で値を書き換えると、すぐに画面で試せる。再読み込みで戻るのは、ブラウザが読み込んだ**コピー**を変えただけで、ファイルは変わっていないから

### 使ったセレクタ
| セレクタ | 例 |
|---|---|
| 要素 | `body`、`form` |
| class | `.delete-button`、`.form-todo` |
| 子孫 | `header h1`、`.done label`、`.list-todo li time`、`form input` |
| 状態 | `:hover`、`:focus` |
| すべて | `*`（`box-sizing` の設定） |

## 2-4 レイアウト

### ボックスモデル
```
margin（外側の余白）> border（枠線）> padding（内側の余白）> content（中身）
```
- 何も書かなくても余白があるのは、**ブラウザの初期設定**（user agent stylesheet）のせい。`ul` の左の 40px は「・」の場所
- `box-sizing: border-box` で、`width` に padding と border を含める（決まり文句）
- `max-width: 560px` ＋ `margin: 0 auto` で、幅に上限をつけて中央に寄せる

### Flexbox
| どこ | 書いたこと | 結果 |
|---|---|---|
| `form` | `display: flex`、`gap`、`align-items: flex-end` | 入力欄とボタンが横に並び、下がそろう |
| `.form-todo` | `flex: 1` | ToDo の入力欄が余った幅を使う |
| `.list-todo` | `display: flex`、`flex-direction: column`、`gap` | カードが縦に並び、間が空く |
| `.list-todo li` | `display: flex`、`align-items: center` | 1件の中身が横に並び、縦の中央でそろう |
| `.list-todo li label` | `flex: 1` | ToDo の文字が余った幅を使う → **期限と削除ボタンが右端に押し出される** |

`display: flex` は**親**に書き、**直接の子**が並ぶ。`flex: 1` は**子**に書き、「余った幅をもらう」という意味。

### スマホ対応
```css
@media (max-width: 480px) {
    form { flex-wrap: wrap; }              /* 入りきらなければ折り返す */
    .form-todo { flex-basis: 100%; }       /* ToDo だけで1行を使い切る → 残りは2行目へ */
    .form-deadline { flex: 1; }            /* 2行目で、期限が余りを使う */
    .form-deadline input { width: 100%; }
}
```
- 気づいた問題：スマホの幅では、期限とボタンが中身の分の幅を取るので、余りをもらう ToDo の入力欄が 57px しかなかった
- `flex-wrap: wrap` だけでは折り返す位置が決まらない。**`flex-basis: 100%` で「ToDo だけで1行」にする**のがポイント
- メディアクエリは外のルールを上書きするので、ファイルのいちばん下に書く
- `<meta name="viewport">` がないと、スマホはパソコン用の幅で描いて縮小する
- 開発者ツールで `Cmd + Shift + M` でスマホの幅にできる

### ダークモードの仕上げ
- `color-scheme: dark`：カレンダーのアイコンなど、ブラウザが描く部品を暗い配色用にする
- `accent-color`：チェックボックスの色を変える
- `:focus` で入力欄の枠をアクセント色に（`outline: none` で消した青い線の代わり）

## 2-5 技術の選択肢

| 選択肢 | どんなものか |
|---|---|
| **素の CSS**（採用） | すべての土台 |
| Sass（SCSS） | 入れ子・変数などを足した CSS。変換して使う |
| Bootstrap | 完成した部品の見た目（`btn btn-outline-danger`） |
| Tailwind CSS | 小さな class を HTML に並べる（`flex p-4 border`）。今の主流の1つ |
| CSS Modules、CSS-in-JS | 部品ごとに CSS を閉じ込める（React などと） |
| テンプレートエンジン（EJS など） | サーバーが HTML を組み立てる |
| React、Vue、Svelte | 画面を部品に分け、「データがこうなら画面はこう」と書く。データを変えると画面が自動で書き換わる |

- **選ぶ基準**：学ぶ量、見た目の自由度、準備（ビルド）の手間、チームと規模
- **素の CSS にした理由**：どの道具も最後は CSS になってブラウザで動く。表示がおかしいとき、開発者ツールで見えるのは CSS
- React はステップ3・4のあとで、ToDo アプリを React で書いたらどうなるかを見て、もう一度紹介する

### CSS の整理のしかた（質問への答え）
CSS は平らに並べるのが普通。階層は `.list-todo li label` のようにセレクタで表す。CSS の入れ子（ネスト）や Sass も使えるが、深くすると上書きしにくくなる。今のファイルには、区画ごとの区切りコメント（`/* ===== フォーム ===== */`）を入れるのがおすすめ。

## つまずいたことと解決方法
| つまずき | 原因 | 解決 |
|---|---|---|
| `<p>` の中の `<ul>` が外に出た | `<p>` には文章の中に入るものしか入れられない | Elements タブで形を確かめ、要素を並べる形に直した |
| `lang="jp"` | `jp` は国の記号 | 言語の記号は `ja` |
| `<header>` がいちばん下に移動していた | 行を移動したときのずれ | `Option + ↑↓` で行を移動、`Shift + Option + F` で字下げを整える |
| フォームのラベルが効かなくなった | 一覧の `<label>` に `id="todo"` をつけ、`id` が4つ重なった | `id` はチェックボックス（指される側）、`for` はラベル（指す側）。`id` は1つずつ違う名前に |
| 文字の色が変わらない | `font-coler` という存在しないプロパティ | 文字の色は `color`。Styles 欄の ⚠ で見つけられる |
| `delete-bottun` → `delete-buttun` | つづりの間違い | 同じ行の `type="button"` と見比べる。`Cmd + Shift + H` でまとめて置き換え |
| ラベルの色が変わらない | `color: 8FA59F;`（`#` がない）、直したあと保存していなかった | 色のコードは `#` から。VS Code のタブの ● で保存忘れに気づく |
| スマホで ToDo の入力欄が狭い | `flex: 1` は「余り」をもらうだけ | メディアクエリで2行に分けた |
