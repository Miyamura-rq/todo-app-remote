## 0-1 ターミナル

### 考え方
- **ターミナル**：文字で命令してパソコンを操作する画面
- **カレントディレクトリ**：今いるフォルダ。命令はここを基準に実行される。プロンプト（`todo-app %` の部分）に表示されている
- **パス**：フォルダやファイルの場所。`/` で区切る。`~` はホームフォルダ（`/Users/recerqa`）
- `.` は今いるフォルダ自身、`..` は1つ上のフォルダ。どのフォルダにも自動で付いている
- **名前が `.` で始まるファイルは隠しファイル**。`ls` では見えず、`ls -a` で見える

### コマンド
| コマンド | 意味 |
|---|---|
| `pwd` | 今いる場所を表示する |
| `ls` / `ls -a` | 中身を一覧表示する / 隠しファイルも含めて表示する |
| `cd フォルダ名` / `cd ..` / `cd ~` | 移動する / 1つ上へ / ホームへ |
| `cat ファイル名` | ファイルの中身を表示する |
| `mkdir フォルダ名` | フォルダを作る |
| `rm ファイル名` | ファイルを削除する。**ゴミ箱に入らず戻せない** |

`cd` はフォルダに、`cat` はファイルに使う。逆にすると `not a directory` / `Is a directory` のエラーになる。

### 出てきた隠しファイル
| ファイル | 役割 | 自分で触るか |
|---|---|---|
| `.DS_Store` | Mac の Finder が自動で作る表示設定 | 触らない |
| `.git` | git の履歴の保存場所 | 触らない（git コマンド経由で操作） |
| `.gitignore` | git で記録しないファイルのリスト | 自分で編集する |
| `.claude` | Claude Code の設定 | たまに |

## 0-2 VS Code と PATH

### エディタの選択肢
| エディタ | 特徴 |
|---|---|
| **VS Code**（採用） | 無料、拡張機能が豊富、最も普及。TypeScript と相性が良い |
| Cursor | VS Code ベースで AI 機能を強化 |
| WebStorm | 有料。TypeScript に強い |
| Vim / Neovim | ターミナル内で動く。慣れるまで時間がかかる |

選ぶ基準：対応言語、情報の多さ、チームの決まり、価格・軽さ

### PATH
- **PATH は「命令を探しに行くフォルダの一覧」**。名前とファイルの対応表ではない
- `ls` と打つと、PATH のフォルダを先頭から順に見て、`ls` という名前のファイルを探して実行する
- 同じ名前のファイルが複数のフォルダにあれば、**PATH の先頭に近い方**が使われる
- フォルダにファイルを置くだけで命令として使えるようになる（`code` も `node` も `/usr/local/bin` に置かれた）

| コマンド | 意味 |
|---|---|
| `echo $PATH` | PATH の中身を表示する（`:` 区切り） |
| `which 名前` / `which -a 名前` | 命令の実体の場所 / 見つかったもの全部を優先順に |
| `code .` | 今いるフォルダを VS Code で開く |

### その他
- VS Code は `.git` や `.DS_Store` を隠す（「触る必要があるか」で判断）。ターミナルは「名前が `.` で始まるか」で隠す
- VS Code 内のターミナルは、開いたフォルダから始まる

## 0-3 git

### git とは
- ファイルの変更履歴を記録する道具。記録1つ1つが**コミット**
- git（道具、自分のパソコン）と GitHub（履歴を置くインターネット上の場所）は別物
- 他の選択肢：Subversion、Mercurial、Perforce。今は事実上 git 一択

### 3つの場所
```
作業フォルダ ──(git add)──▶ ステージ ──(git commit)──▶ リポジトリ（.git）
```
- **ステージがある理由**：変更のうち、**一部だけを選んで**1つのコミットにまとめられるようにするため（集合写真で「写真に入れたい人だけ前に並ばせる」）

### `git status` の見出し
| 見出し | 意味 |
|---|---|
| `Untracked files` | 一度もコミットされていない新しいファイル（git が知らない） |
| `Changes not staged for commit` | 前のコミットから変更されたが、まだ add していない（git は知っている） |
| `Changes to be committed` | add 済み。次のコミットに入る |
| `nothing to commit, working tree clean` | 記録していない変更はない |

### git の動き方
- `git init` したフォルダに `.git` ができ、そのフォルダ以下が対象になる
- git は常に監視しているわけではない。**コマンドを打った瞬間に**「最後のコミット」と「今」を見比べている
- **どの `.git` を使うか**：今いるフォルダから**親フォルダへ順にたどって、最初に見つかった `.git`** を使う。見つからなければ `fatal: not a git repository`
- **コミット ID**：ファイルの中身・メッセージ・作者と日時・1つ前のコミットの ID から計算される**ハッシュ**。1文字でも違えば別の ID になる
- コミットは自分のパソコンの `.git` に保存される。どこにも送っていない

### コマンド
| コマンド | 意味 |
|---|---|
| `git status` | 今の状態を見る |
| `git diff ファイル名` | add 前の変更の中身を見る（`-` 削除、`+` 追加。書き換えは `-` と `+` の組） |
| `git add ファイル名` / `git add .` | ステージに並べる / 今いるフォルダ以下を全部並べる |
| `git commit -m "メッセージ"` | ステージの内容を記録する |
| `git log` | コミットの一覧を見る（`q` で戻る） |
| `git commit --amend -m "メッセージ"` | 直前のコミットを作り直す。**push 前だけ**使ってよい |
| `git config user.name` | コミットに記録される名前を見る |

### 習慣
- `git add .` の後は、**必ず `git status` で確認してから commit**（機密情報をうっかり記録しないため）
- コミットメッセージは「何番目か」ではなく**「何をしたか」**を書く
  - ✕ `1st commit`、`初めてのコミット`、`小修正`
  - ○ `.gitignore の末尾に改行を追加`

## 0-4 GitHub に push

### 考え方
- **ローカルリポジトリ**（自分のパソコン）と**リモートリポジトリ**（GitHub）
- **push**：ローカルのコミットをリモートに送る。**commit しただけでは GitHub は変わらない**
- **認証**：GitHub が「本人か」を確かめる。方法は SSH 鍵、HTTPS ＋ トークン、GitHub CLI。今回は SSH 鍵（登録済みだった）
- **SSH 鍵**は2つで1組
  - `id_ed25519`（秘密鍵）：**絶対に誰にも渡さない**
  - `id_ed25519.pub`（公開鍵）：GitHub に登録する。見られても問題ない

### このプロジェクトの構成（D-0004）
```
todo-app/            ← ローカルだけ（記録・練習用）。コミットは Claude（D-0005）
├── .gitignore       ← app/ を除外
├── docs/ practice/ ...
└── app/             ← 別リポジトリ。GitHub（Miyamura-rq/todo-app, Private）に push する
    ├── .gitignore
    └── README.md
```

### コマンド
| コマンド | 意味 |
|---|---|
| `ssh -T git@github.com` | GitHub と SSH でつながるか確かめる |
| `git init -b main` | 最初のブランチ名を main にしてリポジトリを作る |
| `git remote add origin URL` | GitHub のリポジトリを `origin` という名前で登録する |
| `git remote -v` | 登録先を見る（fetch＝取ってくる先、push＝送る先。普通は同じ） |
| `git push -u origin main` | origin に main を送る。`-u` は初回だけ（以後 `git push` だけで送れる） |

`git log` の `(HEAD -> main, origin/main)` は、ローカルと GitHub が同じコミットにいる＝一致している、という意味。

### `.gitignore` に書くもの
| 種類 | 例 |
|---|---|
| 不要なもの | `.DS_Store` |
| 機密情報 | `.env`、`.env.*` |
| 個人の設定 | `.claude/settings.local.json` |

`.gitignore` 自体はコミットして共有する（ルールを全員で同じにするため。中身に機密情報はない）。

### README と Markdown
- README はリポジトリの説明書。GitHub のトップに表示される
- `# 見出し`（**`#` の後ろに半角スペースが必要**）、`## 小見出し`、`- 箇条書き`

## 0-5 Node.js

### 考え方
- JavaScript を動かすには**実行エンジン**が必要。ブラウザは最初から持っている。**Node.js はブラウザの外で JS を動かす**ためのもの
- ブラウザの JS：画面を操作できる。パソコンのファイルは読めない
- Node.js の JS：ファイルを読み書きしたり、サーバとして動いたりできる。画面は持たない
- **npm**：Node.js と一緒に入る、パッケージ（他の人が作ったプログラム）を取ってくる道具
- **LTS**：長期サポート版。偶数のバージョンが LTS になる。入れたのは v24.21.0

### 選択肢
| 種類 | 選択肢 |
|---|---|
| 実行環境 | **Node.js**（採用）、Deno、Bun |
| 入れ方 | **公式インストーラー**（採用）、バージョン管理ツール（nvm、Volta など）、Homebrew |

### コマンド
| コマンド | 意味 |
|---|---|
| `node -v` / `npm -v` | バージョンを表示する |
| `node` | 対話モード。`.exit` で戻る |
| `node ファイル名` | JS のファイルを実行する |

### JavaScript の最初の一歩
| 書き方 | 意味 |
|---|---|
| `console.log("文字")` | 表示する（Python の `print`） |
| `const 名前 = 値;` / `let 名前 = 値;` | 変えない値 / 変える値に名前を付ける。迷ったら `const` |
| `"文字"` | ただの文字列。`${name}` はそのまま文字として出る |
| `` `こんにちは、${name}` `` | バッククォートで囲むと `${ }` の中の値を埋め込める（Python の f 文字列） |
| `+ - * / %` | 計算。`+` は文字列どうしだとつなげる |
| `// メモ` | コメント |

- `"10"`（文字列）と `10`（数値）は別のもの
- 対話モードで `console.log("こんにちは")` と打つと `こんにちは`（表示）と `undefined`（返した値）の2行が出る。**「表示する」と「返す」は別物**

### エラーの読み方
```
hello.js:3                          ← 何行目か
console.log("初めまして、${name}"です);
            ^^^^^^^^^^^^^^^          ← どこか
SyntaxError: missing ) after argument list   ← 何がおかしいか
    at ...                          ← 文法の間違いでは読まなくてよい
```

## つまずいたことと解決方法
| つまずき | 原因 | 解決 |
|---|---|---|
| `zsh: command not found: code` | `code` が PATH のフォルダになかった | コマンドパレット → `shell command` で登録 |
| `cd。。` が動かない | 全角文字 | コマンドは必ず半角で打つ |
| `git commit --amend` で画面から出られない | Vim が開いた | `i` で入力 → `Esc` → `:wq`（保存して終了）/ `:q!`（保存せず終了）。または `-m` を付けてエディタを開かない |
| `E45: 'readonly' option is set` | 前回の Vim が正しく終わらず `.swp` が残った | `rm .git/.COMMIT_EDITMSG.swp` で削除 |
| 直したのに反映されない | VS Code で保存していなかった（タブに `●`） | `Cmd + S` で保存。git やターミナルは保存された中身しか見ない |
| ファイル末尾に改行がない | 最後の行で Enter を押していない | ファイルは改行で終える |
