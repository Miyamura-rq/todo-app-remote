ToDo にタグを付けられるようにし、タグ・状態・キーワードで一覧を絞り込めるようにします。研修の課題です。SQL の多対多の関連、`JOIN`、クエリパラメータを使った検索を扱います。

## 背景

今の ToDo は文言・期限・完了しか持たず、一覧は `GET /api/todos` で自分の ToDo を `id` 順に全件返しています（`src/server/server.ts`）。件数が増えると、目的の ToDo を探せません。

## やること

### タグ

- 1 つの ToDo に複数のタグを付けられるようにする。同じタグは複数の ToDo に付けられる。
- タグはユーザーごとに持つ。他のユーザーのタグは見えない。
- 画面で、ToDo を作るときと後からタグを付け外しできるようにする。

### 絞り込みと検索

`GET /api/todos` にクエリパラメータを足し、次の条件で絞り込めるようにします。条件は組み合わせられるようにします。

| 条件 | 例 |
|---|---|
| 状態 | 未完了だけ、完了だけ、期限切れ（期限が今日より前で未完了）だけ |
| タグ | 指定したタグが付いているものだけ |
| キーワード | 文言に含まれる文字で検索する（大文字・小文字を区別しない） |
| 並び順 | 作成順、期限順（期限なしは最後） |

画面にも絞り込みの入力欄を置きます。

### 決めてほしいこと（PR の本文に書く）

- テーブルの設計（どのテーブルを足し、主キーと外部キーをどうしたか、なぜそうしたか）
- タグを削除したとき、付いていた ToDo の側をどうするか
- キーワードに `%` や `_` が入っていたときにどう扱うか

## 完了条件

- [ ] 1 つの ToDo に 2 つ以上のタグを付けられ、付けたタグが一覧に表示される
- [ ] 同じ名前のタグを同じユーザーが 2 つ作れない（DB の制約で止めている）
- [ ] 他のユーザーのタグを、API を直接呼び出しても自分の ToDo に付けられない
- [ ] 状態・タグ・キーワード・並び順を組み合わせて絞り込んだ結果が正しい（どの組み合わせで確かめたかを PR に書く）
- [ ] キーワードに `%` を入れても、全件が返らない
- [ ] SQL に利用者の入力を文字列でつなげていない（すべて `$1` などのプレースホルダーで渡している）
- [ ] `db/schema.sql` を流し直した DB で、README の手順どおりに起動できる
- [ ] テーブル設計と「決めてほしいこと」の 3 点が PR の本文に書かれている

## 依存・順序

- ログイン・登録の画面ができている必要があります（今は `/api/todos` が 401 を返し、画面に一覧が出ません）。
