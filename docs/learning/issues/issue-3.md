# Issue #3 画像から ToDo の候補を抜き出す（ステップ10）

写し: 2026-10-28（学習者が貼りつけたもの。`app/` のリポジトリは非公開で、Claude は GitHub の Issue を直接読めないため、ここに残す）
元: https://github.com/Miyamura-rq/todo-app/issues/3

---

手書きのメモやホワイトボードの写真、スクリーンショットをアップロードすると、Claude API で ToDo の候補（文言と期限）を抜き出し、確かめてから登録できるようにします。研修の課題です。ファイルのアップロード、LLM の呼び出し、LLM の出力を検証して扱うことを扱います。社内の案件（請求書の画像から項目を読み取る処理など）と同じ形の処理です。

## 背景

今の ToDo は、画面のフォームから 1 件ずつ文言と期限を入力して登録します（`public/index.html`、`src/client/main.ts` の `postTodo`）。会議のメモやホワイトボードに書いたタスクを ToDo にするには、手で打ち直す必要があります。

## やること

### アップロード

- 画面から画像（JPEG・PNG）を 1 枚選んでアップロードできるようにする。
- サイズの上限と受け付ける形式をサーバーで確かめ、範囲外なら理由がわかるエラーを返す。

### 抜き出し

- サーバーから Claude API（Messages API）に画像を送り、ToDo の候補を JSON で受け取る。1 件ごとに文言と期限（なければ空）を持つ。
- 「来週金曜」のような相対的な日付は、アップロードした日を基準に日付に直す。
- API キーは `.env` で渡し、リポジトリに入れない。`.env.example` には項目名だけを書く。API キーは講師から受け取ってください。

### 確かめてから登録する

- 抜き出した候補を画面に一覧で出し、利用者が文言・期限を直したり、不要な候補を外したりしてから登録する。
- 候補をそのまま DB に登録しない。

### LLM の出力の扱い

LLM は、形式が違う JSON、存在しない日付、空の文言などを返すことがあります。

- サーバーで受け取った出力を検証し、形式が違う候補は登録の画面に出さない（または直すよう表示する）。
- 抜き出しに失敗したとき（API のエラー、タイムアウト、ToDo が 1 件も見つからない）に、画面に理由を表示する。

## 完了条件

- [ ] 手書きのメモの写真から抜き出した候補が画面に出て、直してから登録できる（使った画像と結果を PR に貼る）
- [ ] 「明日」「来週金曜」のような書き方が、アップロードした日を基準にした日付になる
- [ ] 上限を超えるサイズの画像と、画像でないファイルを送ると、Claude API を呼び出さずにエラーを返す
- [ ] Claude API が形式の違う JSON や存在しない日付（例: `2026-02-30`）を返したときに、サーバーが 500 を返さず、DB に不正なデータが入らない。これを、Claude API の応答を差し替えたテストで確かめている
- [ ] Claude API がエラーを返したとき・応答しないときに、画面に理由が表示される
- [ ] API キーがコミットの履歴に含まれていない
- [ ] 1 回の抜き出しにかかった時間とトークン数を、PR に書いている（実際に 3 枚以上の画像で測った値）

## 依存・順序

- ログイン・登録の画面ができている必要があります。
- リストの共有の課題が終わっていれば、登録先のリストを選べるようにしてください。終わっていなければ不要です。

## 別の Issue で検討するもの（スコープ外）

- PDF や複数枚の画像のアップロード
- アップロードした画像の保存（今回は抜き出したら捨ててよい）
- 抜き出しの精度の評価の仕組み
