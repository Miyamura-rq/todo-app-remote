# D-0018 学習プランにステップ7「ログイン（認証）」を足し、公開を8、品質を9にする

日付: 2026-10-14
置き換える決定: D-0001（ステップ7・8の内容と順番。ステップ0〜6と、進め方の部分はそのまま）

## 決定
ステップ7以降を次のようにする。

| ステップ | 学ぶこと | ゴール |
|---|---|---|
| 7. ログイン（認証） | ユーザーの登録とログイン、パスワードの安全な保存、Cookie とセッション、users テーブルと ToDo のつながり | 自分の ToDo だけを見て操作できる |
| 8. 公開 | ホスティング、環境変数 | インターネット上でアクセスできる |
| 9. 品質 | 入力チェック、エラー処理、テスト、セキュリティ | 壊れにくく、安全にする |

- ステップ8以降を実際に行うかは未定。ステップ7を終えた時点で決める。
- ログインの作り方（自分で作るか外部サービスを使うか、セッションか JWT か）は、ステップ7の始めに選択肢を示して決める。仕組みが見える「自分で作る＋セッション」になる見込み。
- 公開先・DB についての会社の決まりは、ステップ8に入る前に確認する（D-0001 では「ステップ7の前」だったもの）。
- テストのコマンドはステップ9で決める。

## 理由
- 学習者がログイン（認証）を学びたいと希望した。
- ログインは「公開して他人が触れるようになる」ときに必要になる機能なので、公開の前に作るのが実際の開発の順番に近い。公開した時点で、自分の ToDo を他人に見られたり消されたりしない。
- ステップ6の DB の続き（users テーブル、テーブル同士のつながり）として学べる。
- パスワードのハッシュや Cookie など、品質（安全）の内容の一部をログインのステップで先に扱える。

## 却下した案
- 7 公開 → 8 ログイン → 9 品質: 早く公開できるが、ログインがない間は URL を知っている人なら誰でも ToDo を消せる。
- 7 品質 → 8 ログイン → 9 公開: 安全の基礎を先に学べるが、公開がかなり先になる。
- ほかの候補（React、チーム開発の流れ、リマインド、Docker、CI）は今回は足さない。必要になったら追加する。
