# D-0023 書いたコードは先にレビューし、直すところがなくなってから学習者が動かして確かめる

日付: 2026-10-27
補足する決定: D-0002（ヒントとレビューだけを行う）、D-0021（課題は確かめ方まで最初に示す）

## 決定
- 学習者が「書いた」と言ったら、Claude はまずコードを読んでレビューする。課題の「確かめ方」（curl など）は、レビューで直すところがなくなってから学習者が実行する。
- レビューのときに Claude が自分で確かめるのは、学習者の確かめ方の結果を変えないものだけにする。例：`tsc --noEmit`（変換したファイルを書き換えない）、SQL を `PREPARE` で確かめる（実行しない）。
- 学習者が予想してから試す curl や、行を足す SQL を、Claude が先に送らない。失敗した INSERT でも連番は進むので、予想の答えが変わる。
- 課題のガイドの「確かめ方」は、「レビューのあとに行う」と書いて示す。

## 理由
- 7-3 の1回目のレビューのあと、Claude は「直したら①〜⑥を試して、結果と予想の答えを教えて」と返した。学習者から「これからは、レビューしてから検証する形にして」と依頼があった。
- 誤りが残ったまま確かめ方に進むと、500 が返るだけになる。予想（Q1〜Q4）を確かめる練習にならない。
- 1回目のレビューでは、Claude が学習者のサーバーに登録の curl を送った。失敗したので行は増えなかったが、成功していれば `c@example.com` が先に登録されていた。そうなると、学習者は①の結果を自分で見られなかった。

## 却下した案
- これまでどおり、直したら確かめ方まで進め、その結果とあわせてレビューする：誤りが多いうちは、確かめ方の結果が 500 ばかりになり、時間がかかる。
- レビューのときに Claude が確かめ方も実行し、結果を伝える：学習者が予想して自分で確かめる練習がなくなる。
