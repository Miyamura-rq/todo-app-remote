# D-0021 課題は、最初から全体の流れ（目的・手順・骨組み）まで示してガイドする

日付: 2026-10-27
補足する決定: D-0002（ヒントとレビューだけを行う）、D-0016（書き方の型を先に示す）

## 決定
課題を出すときは、最初から次のところまで示す。

- 課題の目的（何を確かめるのか、何を作るのか）
- 学習者がすでに書いたコードとの対応（どこが同じで、どこが違うか）
- 使う部品の役割（たとえを使う）
- やることを日本語の手順に分ける（1つの処理を ①②… に）
- コメントつきの骨組みと、何行くらいで書けるかの目安（中身のコードは学習者が書く）
- 書いたあとの確かめ方（`npm run build`、curl など）

答えのコードは書かない。ヒントは、このガイドより先の段階として出す。

## 理由
- 7-1 の練習用のルートで、型と仕様の表だけを示したところ、学習者が「そもそも何を書いたらいいのかわかってない」となった。`(res, req)` の順番、`await res.cookie(...)`、`res.headers.cookie()` など、形そのものを手探りしていた。場所だけを示すヒント1でも進めなかった。
- 手紙と封筒のたとえ、既存の `/api/todos` との対応、①② の手順、骨組みを示したあとは、1回でほぼ書けた（残りは `"` の抜け1つ）。
- 学習者から「学習全体としてこの返答くらいの感じで最初からガイドするようにして」と依頼があった。
- これまでも 5-1「全くわからない」、5-3「`res.json` に何を入れるか伝わらない」、6-3「返すものの型を教えてもらえないと分かるわけない」、6-5「何がしたいのか全くわからない」と、全体像がないまま書き始めてつまずく例が続いていた。

## 却下した案
- これまでどおり型と仕様だけを示し、分からないときにヒントで補う: 全体像がないまま書き始めると、つまずきが「形が分からない」ことに集中し、学びたい中身（Cookie の流れなど）に時間を使えない。
- 答えのコードを示して写してもらう: 自分で書く練習にならない（D-0002 のメンターの方針は変えない）。
