# D-0015 クライアントとサーバーの TS を分け、どちらも tsc で変換する

日付: 2026-10-13

## 決定
- `src/client/main.ts` → `public/main.js`、`src/server/server.ts` → `dist/server.js` に、それぞれ `tsc` で変換する。
- tsconfig はフォルダごとに置く（`src/client/tsconfig.json` は `dom` あり、`src/server/tsconfig.json` は `dom` なし・`module: nodenext`・`types: ["node"]`）。ルートの `tsconfig.json` は消す。
- サーバーは `node dist/server.js` で動かす。`dist/` は git に入れない。
- D-0011（変換した JS は git に入れない）はそのまま。

## 理由
- 今の設定のままでは、サーバーのコードが `public/` に出てしまい、誰でもダウンロードできる。
- 「tsc は検証して変換（実行はしない）」を、クライアントとサーバーの両方で体験できる（S-0011 の要復習）。
- 本番でも変換済みの JS を動かす形が素直で、ステップ7につなげやすい。
- ブラウザとサーバーで使える機能が違う（`document` の有無など）ので、設定を分けるのが自然。

## 却下した案
- B：Node.js 24 で `.ts` を直接動かす（型を消すだけ）: 型チェックしなくても動いてしまい、使えない書き方もある。
- C：`tsx` などの道具で直接動かす: 道具が増え、裏で何が起きているか見えにくい。
