# D-0027 新しい書き方は予想のクイズを出さず、説明（必要なら図）→ 実装の流れにする。確かめ方には期待する結果も添える

日付: 2026-10-31
補足する決定: D-0021（課題のガイド）
置き換える決定: D-0023 のうち「学習者が予想して試す」部分

## 決定
- 新しい書き方・コマンド・SQL は、Claude が先にわかりやすく説明する。今のデータでの例と、その結果を見せる。必要なら図も使う。そのあとで学習者が実装する。
- 実行する前に結果を予想させる問い（「何行出ますか」「何番のステータスになりますか」など）は出さない。
- 確かめ方のコマンドを出すときは、期待する結果（答え）も一緒に示す。学習者は実行して、違ったところだけ伝えればよい。
- 変えないもの
  - 学習者がコードを書き、Claude はレビューする（D-0002）。
  - 課題は、目的・手順・骨組みまで最初に示す（D-0021）。
  - 書いたら先にレビューし、確かめ方の実行は直すところがなくなってから（D-0023）。
  - セッションの終わりの理解度チェック（D-0002）は、学んだことの確認なので続ける。

## 理由
- 学習者の言葉：「新たなコマンドの予想をさせられるより、（必要に応じて図解等を用いて）わかりやすく新規コードの説明→実装の流れにしてもらいたい」「長い文章で、知らない知識をあてるクイズしてるとかなり疲れる」。
- 8-2・8-3 でも、学習者は予想と結果を貼らずに「答え合わせ」を選んでいた。8-4 A では、⓪〜④ と Q1〜Q3 を一度に出して「話が長くてわからなかった」と言われた。
- まだ知らないことの予想は当てずっぽうになりやすい。疲れるわりに、学びにつながりにくい。

## 却下した案
- 予想の問いを続ける：上の理由。
- 課題を毎回1段ずつ短く出す：学習者が「今回だけでいい」と答えた。いつもは D-0021 の出し方のまま。
