# D-0025 ステップ8〜10はメンターの Issue #1〜#3 を順に行い、ブランチと PR で進める

日付: 2026-10-28
補足する決定: D-0024（機能のステップを足す）
置き換える決定: D-0024 のうち「テストのコマンドは最終ステップ（品質）で決める」

## 決定
- 次の3つの機能を、順にステップ8・9・10 として行う。研修の課題で、学習者のメンター（人）が `app/` の GitHub の Issue に書いたもの。

| ステップ | Issue | 内容 |
|---|---|---|
| 8 | #1 | タグと、絞り込み・検索 |
| 9 | #2 | リストの共有（招待・権限）と、リアルタイムの反映 |
| 10 | #3 | 画像から ToDo の候補を抜き出す（Claude API） |

- Issue の本文は `docs/learning/issues/issue-<番号>.md` に写して残す。`app/` のリポジトリは非公開で、Claude は GitHub の Issue を直接読めないため。
- 進め方は、Issue が求めるとおりにブランチを切り、PR を出す。
  - 流れ：ブランチを作る → コミット → ブランチを push → GitHub で PR を作る → メンターのレビュー → マージ
  - `app/` のコミット・push・PR は学習者が行う（D-0005、D-0013）。
- Issue の「決めてほしいこと」と、PR の本文は学習者が書く。
  - Claude は選択肢と、選ぶときの基準を示す。
  - 学習者が決めたものをレビューする。
  - PR の本文の文章は書かない。
- これまでの進め方（D-0002 メンター、D-0021 課題のガイド、D-0023 先にレビュー）は、そのまま続ける。
  - 課題の実装の書き方は、これまでどおり Claude がおすすめを決める（D-0010）。
- テストは、Issue #2 が求めるので、ステップ9 で道具とコマンドを決めて始める（D-0024 では最終ステップだった）。

## 理由
- 学習者がメンターから3つの課題を受け取り、順に追加すると決めた。
- 3つの Issue はどれも PR の本文に判断と理由を書くことを求めている。メンターが見たいのは学習者の判断なので、Claude が決めて書くと課題の意味がなくなる。
- Issue #2 の完了条件に「API を呼び出すテストで確かめている」がある。Issue #3 にも「応答を差し替えたテスト」がある。そのため、テストは最終ステップまで待てない。

## 却下した案
- 「決めてほしいこと」も、Claude がおすすめを決める（D-0010 のまま）：研修の課題では、学習者が自分で判断した理由を書くことが求められている。
- これまでどおり `main` に直接コミットする：Issue が PR を前提にしている。メンターのレビューも PR で受ける。
