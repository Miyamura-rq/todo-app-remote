# D-0030 ステップ9 からは、コードの多くを Claude が書いて解説し、大事なところ（★）だけ学習者が書く

日付: 2026-11-01
置き換える決定: D-0002（「学習者のコードを書き換えず、ヒントとレビューだけ」の部分）、D-0005・D-0013（「`app/` のコミットと push は学習者」の部分）

## 決定
- ステップ9（Issue #4）からは、実装の多くを Claude が書く。書いたらすぐ、何を変えたか、前のコードとの対応（前 → 後）、新しい書き方の型を解説する。
- 各ステップで、学習に大事なところを ★ として決め、そこだけ学習者が書く。★ はこれまでどおり、課題の出し方（D-0021・D-0028）→ レビュー（D-0023）→ 期待する結果つきの確かめ方（D-0017・D-0027）で進める。
- Claude が書いたコードは、Claude が `tsc`・起動・curl などで動くことを確かめ、結果を見せる。
- `app/` のコミットと push も Claude が行う（目的ごとに分ける）。
- Issue の「前提として調べること」は Claude が図と今のコードとの対応で説明し、学習者が自分の言葉で言い直す。PR の本文と「メンターに説明できる」ことは、これまでどおり学習者（D-0025）。
- セッションの終わりの理解度チェックは続ける（D-0002・D-0014）。

## 理由
- 学習者の言葉：「時間がないので、多くのコーディングをそっち側でしてもらい、解説してもらう形に変更しようと思います」「必要に応じて重要なコーディングを一部僕にやらせて学習するような形に」。
- ステップ9〜12 は、技術スタックを Drizzle・Hono・React Router に移す作業で、書く量が多い。全部を学習者が書くと時間が足りない。Issue が求めているのは、それぞれの技術を自分の言葉で説明できることと、PR を出すこと。

## 却下した案
- これまでどおり学習者が全部書く：時間が足りない。
- Claude が全部書く：Issue の完了条件に「メンターに説明できる」があり、手を動かす部分がないと身につきにくい。
