# D-0029 応答の手順は CLAUDE.md の1つの節に場面の順でまとめ、別のファイルにしない。STATUS.md には CLAUDE.md にあることを書かない

日付: 2026-10-31
補足する決定: D-0002、D-0016、D-0017、D-0021、D-0023、D-0027、D-0028（中身は変えず、書く場所と並べ方だけを決める）

## 決定
- 課題の出し方とレビューの仕方の決まりを、CLAUDE.md の「応答の手順」に、場面の順の番号つきの手順としてまとめる：ステップを始める → 項目を始める・課題を出す（①完成形 → ②必要な要素 → ③今やること）→ 選択肢があるとき → 書いたらレビュー → 直すところがなくなったら確かめ方 → セッションの終わり。どの場面でも守ること（図、軽い知識、デザインの値）は手順の下に置く。
- 応答の手順は、別のファイル（docs の Markdown や .docx）に分けない。
- 変わらない情報（仕様、DB、リポジトリ、SSH、サーバーの起動のしかた、PC の切り替え）は CLAUDE.md に置く。STATUS.md には今の状態（現在地・次にやること・未解決）だけを書き、CLAUDE.md にあることは書かない。

## 理由
- 学習者の言葉：「CLAUDE.md 長くなりすぎてたりしない？重複ないようにして」「応答の手順を別の docx にして参照させた方が効率よければ、そういう検討もして」。
- 応答の手順は毎回の返事で使う。別のファイルにして場所だけ書くと、毎回そのファイルを開く手間が増え、開き忘れると守られない。`@` で読み込むと中身は毎回読み込まれるので、量は減らない。.docx は Claude が直接読めず、変換の手間が増える。
- 長くなっていた原因は重複だった。STATUS.md の「進め方」の行が CLAUDE.md のルールをほぼそのまま繰り返し、ほかにも作成物・リポジトリ・テストコマンド・docs の場所が両方にあった。CLAUDE.md の中でも、確かめ方を出すときが D-0021（課題を出すとき）と D-0023（レビューのあと）の別々の行にあり、読み比べないと順番がわからなかった。
- 整理の結果、毎回読み込まれる CLAUDE.md と STATUS.md の合計は 12,654字 → 8,998字（約3割減）。

## 却下した案
- 応答の手順を別の Markdown ファイルにして `@` で読み込む：量は減らず、見る場所が1つ増える。
- 別のファイルにして場所だけ書き、必要なときに読む：手順は毎回必要なので、読み忘れると守られない。
- .docx にする：Claude が直接読めない。
