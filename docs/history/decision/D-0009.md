# D-0009 画面は ToDo の配列（データ）から作り直す

日付: 2026-10-07

## 決定
ToDo の正しい情報は配列 `todos`（データ）に持ち、追加・完了・削除はすべて「配列を書き換える → `render()` で一覧を作り直す」の形で作る（3-4 で学習者が選択）。

あわせて、チェックボックスとラベルは `<label>` で `<input>` を包んでつなぐ（id と `for` は使わない）。

## 理由
- ステップ5・6でサーバや DB から受け取るのは配列のデータなので、受け取ったら `render()` するだけで済む
- 処理が「データを変える → 作り直す」の1パターンにそろい、画面とデータがずれにくい。残り件数も 3-1 の `countRemaining(todos)` をそのまま使える
- React の「データを変えると画面が作り直される」考え方を手で体験でき、あとで React を紹介するときに便利さが実感できる
- label で包むと、ToDo ごとに違う id を作る必要がない

## 却下した案
- A. 画面（DOM）を直接書き換える：最初は短く書けるが、正しい情報が画面に散らばり、ステップ5でデータから画面を作る処理を書き直すことになる
- id と `for` でつなぐ：ToDo ごとに重ならない id を JS で作る手間がある
