# S-0019 7-1 ログインの仕組み（Cookie の流れ、パスワードの保存）

日付: 2026-10-27

## やったこと
- 練習用のルート `/practice/set`（Cookie `userId=3` を渡す）と `/practice/check`（届いた Cookie ヘッダを返す）を学習者が書き、curl（`-i`・`-c`・`-b`）と開発者ツールで Cookie の流れを確かめた
  - 型と表だけでは「そもそも何を書いたらいいのかわかってない」となり、たとえ・既存コードとの対応・手順・骨組みでガイドした。以後、課題は最初からこの形で示す（D-0021）
  - つまずき：`(res, req)` の順番、`await res.cookie(userId, 3)`、`res.headers.cookie()`、`userId` の `"` 抜け、変数名を変えたあとの `result` の残り（build が失敗して `npm run dev` が start まで進まず、curl が `Couldn't connect`）
  - Q1〜Q3（Cookie なしで `{}`、書き換えた値をサーバーは見分けられない、`userId=3` ならなりすませる）は「概ね想定通り」
- パスワードをそのまま保存しない理由を説明し、`node -e` で SHA-256 のハッシュとソルトを確かめた。遅いハッシュ（bcrypt・scrypt・Argon2）を紹介
  - Q4（なぜ照合できるか）は正解。Q5 で「ソルトと `req.cookie` を合わせる」と回答 → 混ぜるのは入力されたパスワード。パスワードを使うのはログインの1回だけで、Cookie はそのあと毎回、と整理
- 早見表 `docs/learning/reference/auth.md` に Cookie の流れ・書き方・確かめ方、パスワードの保存を追加
